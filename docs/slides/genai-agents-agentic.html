Three Words, Three Different Things.

Orientation

Where this starts

The words are on every CV. The answers aren’t.

Open any LinkedIn profile or résumé: Generative AI · AI Agents · Agentic AI. Then ask one plain question, and the room goes quiet.

Is ChatGPT an AI agent?

Sometimes yes, sometimes no — and the deciding factor isn’t the model.

How is this different from a Zapier automation?

Both call APIs and act without you. So what actually changed?

Is “AI agent” just another word for “agentic AI”?

The same person will use both in one sentence, meaning two different things.

None of these are trick questions — they are the subject. If you can answer all three in a sentence each by the end, the session did its job.

PART ONE

Generative AI

A model that produces content. Powerful, and more limited than it looks.

Generative AI

Definition

It produces content instead of labelling it

"Generative" is a contrast with discriminative. A spam filter tells you which bucket an email belongs in — it picks from options you defined. A generative model writes the email.

The output space isn't a list of categories. It's every sequence of words the model could produce.
Same idea across media: text, code, images, audio, video. This session stays with language models, because that is where agents are built.
Generative AI

Mechanism

One trick, repeated: predict the next token

Generative AI

What follows from that

Three limits, and they are structural

  1. No memory

    Every API call is independent. A "conversation" is you re-sending the entire history on each turn. The model remembers nothing on its own.

  2. No actions

    It emits text. It cannot read your database, call your API, or send an email. There is no mechanism by which it could.

  3. No goals

    Nothing persists between calls, so there is nowhere for a goal to live. What looks like intent is a pattern in the text it was given.

Everything in the next two parts of this session exists to work around one of these three. That is the whole plot.
Generative AI

Calibration

Where it earns its keep, and where it doesn't

Reliable

  • Transforming text you supply
  • Drafting, rewriting, summarising
  • Pulling structure out of prose
  • Writing and explaining code
  • Classifying with a clear rubric

Unreliable

  • Facts outside its training data
  • Anything that happened recently
  • Long arithmetic, exact counting
  • Being a system of record
  • Knowing what it doesn't know
The pattern: it is strong on text you put in front of it, weak on facts it has to supply itself. Retrieval and tools exist to move work from the right column to the left.
Generative AI

Demo · lesson 00

The entire API surface is one request

# text in, text out. no memory, no tools, no loop.
response = client.messages.create(
    model="claude-opus-5",
    max_tokens=1000,
    messages=[{"role": "user", "content": "What is a token?"}],
)

# the reply is a LIST of typed blocks, not a string
# -> [TextBlock(type='text', text='A token is ...')]
Run this twice and the second call knows nothing about the first. Everything from here on is scaffolding around this one request.

PART TWO

AI Agents

Giving the model a way to affect the world — and keeping the switch in your hands.

AI Agents

Fixing limit №2

A tool is a function, described in words

You hand the model a list of functions it may request: a name, a description, and the shape of the arguments. The description is not documentation for you — it is the prompt the model reads when deciding what to call.

@beta_tool
def get_weather(location: str, unit: str = "celsius") -> str:
    """Get the current weather for a location.

    Args:
        location: City and region, e.g. "Pune, MH".
    """
Vague descriptions produce wrong tool calls. Most "the model chose badly" bugs are actually docstring bugs.
AI Agents

The core mechanic

The loop that makes it an agent

AI Agents

The detail most explanations skip

"The AI booked my flight." It didn't.

The model produced a block of JSON naming a function and its arguments. Your software read that JSON, decided to honour it, and called the airline's API.

# what the model actually emits — inert text:
{"type": "tool_use", "name": "book_flight",
 "input": {"to": "NRT", "passengers": 2}}
Three things follow. Your guardrails live in your code, because that is the only place execution happens. Approval gates go in the tool, not the prompt. And when it misbehaves, suspect your tool before the model.
AI Agents

Anatomy

Five parts, and one of them is always skipped

Model

Decides what to call and reads the results.

Tools

What it may request, described well enough to choose between.

Loop

Call, execute, feed back, repeat until done.

State

The message history you re-send, since the model holds none.

Bounds

Iteration cap, spend cap, a log of every call. Skipped almost every time.

An agent without bounds is a billing incident with a countdown on it.

AI Agents

Demo · lesson 03

Watch the turns go past

user       Should I take a jacket in Pune today?
assistant  [tool_use] get_weather(location="Pune, MH")
user       [tool_result] 22 degrees celsius and clear
assistant  No jacket needed — it's 22C and clear.

Four turns, two API calls, one function executed by your code. The middle two lines are the entire difference between a chatbot and an agent.

Note the roles: tool results come back as a user message. From the model's side, your code is just another participant in the conversation.

PART THREE

Agentic AI

Handing over the control flow — deliberately, and less often than you'd think.

Agentic AI

Definition

It's an adjective, and it's a matter of degree

Agentic describes how much of the control flow the model owns: which steps run, in what order, and when to stop.

It is not a newer technology than AI agents, and it is not something you install. Same models, same tools — different author of the arrows.
Which is why "is this agentic?" is a bad question, and "how much of my control flow did I hand over, and what did I get for it?" is a good one.
Agentic AI

The real distinction

Who wrote the arrows?

Agentic AI

Calibration

How agentic is it, really?

  • Summarise every incoming ticket. Fixed pipeline. Not agentic — the model fills a slot you defined.
  • Route a ticket to one of three teams. Barely. One decision, from a menu you wrote.
  • Standard RAG: retrieve, then answer. Not agentic. The order is fixed; retrieval always happens exactly once.
  • Agentic RAG: model decides whether and what to search, and how often. Yes — the retrieval decision moved to run time.
  • Coding agent: plans, edits, runs tests, reads failures, re-plans. Strongly agentic. Nobody wrote that sequence.
Notice that the last two use exactly the same tools as the versions above them. What moved was the decision, not the capability.
Agentic AI

Before you build

Four questions. One "no" is enough.

  1. Complexity

    Is the task genuinely hard to specify in advance? If you can draw the flowchart, draw the flowchart.

  2. Value

    Does the result justify the latency and the token bill? An agent costs several times a single call.

  3. Viability

    Is the model actually good at this task? Autonomy multiplies whatever quality you started with — in both directions.

  4. Cost of error

    Can a mistake be caught and undone? Irreversible actions need a human in the loop, not more autonomy.

Most production "agents" should have been workflows. The workflow is cheaper, testable, and it fails in ways you can reproduce on a Tuesday afternoon.
Corrections

Corrections

Six claims to push back on

  • "Agentic AI is the next generation after AI agents."
    No. It's a property of a system, not a successor product. They aren't on a timeline together.
  • "The agent executes the action."
    No. It emits a request. Your code executes — which is exactly where your security boundary sits.
  • "Agentic means it thinks, wants, has goals."
    No. The goal is text in a prompt and structure in your loop. Nothing persists between calls.
  • "More autonomy is better."
    No. Autonomy is a price you pay when a task can't be specified — not a feature you upgrade to.
  • "I wrote a clever prompt, so I built an agent."
    No tools and no loop means no agent. A named persona is still a single API call.
  • "RAG is agentic."
    Only if the model decides the retrieval. Fixed retrieve-then-answer is a pipeline.

Corrections

Reality check

What actually goes wrong in production

Errors compound

95% accurate per step is 60% over ten steps. Long autonomous chains are where this becomes visible.

Cost runs away

A loop with no iteration cap and a paid API on the other end. Set a spend limit before your first run.

No audit trail

When routing goes wrong, someone has to say why. Design the log before you write the loop.

Injection via tool results

Text a tool returns is untrusted input. A fetched page can carry instructions — treat results as data, never orders.
